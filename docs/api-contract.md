# API Contract (Proposed)

Prefix: `/api/v1`. The service exposes a REST API with OpenAPI specification automatically generated by FastAPI.

## Global conventions
- **Encoding & Media:** JSON request and response payloads (`Content-Type: application/json`).
- **Identifiers:** Canonical UUIDv4 strings for all resource IDs.
- **Timestamps:** ISO-8601 strings in UTC (e.g. `2026-10-27T12:00:00Z`).
- **Authentication:** `Authorization: Bearer <jwt-token>` header for protected endpoints.
- **Idempotency:** Sensitive write endpoints require the `Idempotency-Key: <unique-uuid-or-string>` header.
- **Pagination:** Query parameters `page` (default 1) and `page_size` (default 20, max 100) with deterministic ordering (`created_at DESC, id DESC`).
- **Error shape:** Standardized error response format:
  ```json
  {
    "error": {
      "code": "SLOT_ALREADY_BOOKED",
      "message": "The selected doctor slot is no longer available.",
      "request_id": "req_01j9a4k7..."
    }
  }
  ```

## 1. Authentication and account (`/auth`)

| Method | Path | Access | Description |
|---|---|---|---|
| POST | `/api/v1/auth/register` | Public (rate-limited) | Register a new user (`patient` role default) |
| POST | `/api/v1/auth/login` | Public (rate-limited) | Authenticate user; returns JWT or prompts MFA challenge |
| GET | `/api/v1/auth/me` | Authenticated | Retrieve current user profile and role |
| POST | `/api/v1/auth/mfa/enroll` | Authenticated (doctor/admin) | Initiate TOTP MFA setup (returns URI/seed once) |
| POST | `/api/v1/auth/mfa/confirm` | Authenticated | Submit first TOTP verification code to enable MFA |

## 2. Doctors and availability (`/doctors`)

| Method | Path | Access | Description |
|---|---|---|---|
| GET | `/api/v1/doctors` | Public / Authenticated | Search doctors by specialization, name, or verification status |
| GET | `/api/v1/doctors/{doctor_id}` | Public / Authenticated | Retrieve doctor public profile and consultation fee |
| GET | `/api/v1/doctors/{doctor_id}/slots` | Public / Authenticated | List available slots for a doctor within a date range |
| POST | `/api/v1/doctors/me/slots` | Doctor | Create one or multiple availability time slots |
| PATCH | `/api/v1/doctors/me/slots/{slot_id}` | Owning Doctor / Admin | Update slot time or mark blocked (unbooked only) |
| DELETE | `/api/v1/doctors/me/slots/{slot_id}` | Owning Doctor / Admin | Delete an unbooked availability slot |

## 3. Booking and consultation (`/bookings`, `/consultations`)

| Method | Path | Access | Description |
|---|---|---|---|
| POST | `/api/v1/bookings` | Patient (`Idempotency-Key` required) | Atomically reserve slot and create consultation |
| GET | `/api/v1/bookings/{booking_id}` | Owner / Assigned Doctor / Admin | Retrieve booking status and details |
| POST | `/api/v1/bookings/{booking_id}/cancel` | Booking Owner / Admin | Cancel booking and release slot back to available |
| GET | `/api/v1/consultations` | Patient / Doctor scoped | List consultations filtered by caller's identity |
| GET | `/api/v1/consultations/{id}` | Patient / Assigned Doctor / Admin | Get consultation detail and medical record summary |
| POST | `/api/v1/consultations/{id}/confirm` | Assigned Doctor | Confirm appointment (`booked` → `confirmed`) |
| POST | `/api/v1/consultations/{id}/start` | Assigned Doctor | Begin consultation (`confirmed` → `in_progress`) |
| POST | `/api/v1/consultations/{id}/complete` | Assigned Doctor | Complete consultation (`in_progress` → `completed`) |
| POST | `/api/v1/consultations/{id}/no-show` | Assigned Doctor / Admin | Mark patient no-show (`confirmed` → `no_show`) |

`POST /api/v1/bookings` requires a patient access token and an `Idempotency-Key` header. Its body
contains `doctor_id` (UUID), `slot_id` (UUID), and an optional `reason` no longer than 2,000
characters. It returns the created consultation (`id`, `patient_id`, `doctor_id`, `slot_id`,
`status`, optional `reason`, `created_at`, and `updated_at`) with `201 Created`. A matching
completed retry returns the exact stored representation with `200 OK`; a reused key with a changed
body, a slot owned by a different doctor, or an unavailable slot returns `409 Conflict`. Booking
is limited to future slots whose status is `available`.

## HTTP status code semantics
- `200 OK`: Request succeeded.
- `201 Created`: Resource successfully created.
- `400 Bad Request`: Malformed payload or invalid parameters.
- `401 Unauthorized`: Authentication credentials missing or invalid.
- `403 Forbidden`: Authenticated, but lacking permissions for resource.
- `404 Not Found`: Resource does not exist (or concealed by policy).
- `409 Conflict`: Slot already booked, idempotency payload mismatch, or state conflict.
- `422 Unprocessable Entity`: Schema/field validation error.
- `429 Too Many Requests`: Rate limit threshold exceeded.
- `500 Internal Server Error`: Internal server error (redacted from client).
- `503 Service Unavailable`: Temporary upstream dependency outage.
